### 1.3 已确认的视觉基底

用户在多轮静态稿后明确回到上传的第一版卡片界面，并要求精修、加必要动效、构建原生版。该决定替代后续开放式G/G2/G3静态方向；不把静态稿的拓扑写进App。保留原生内联标题、观察卡、恢复/步数双卡、周活动卡与底部系统三标签；蓝色仍是操作主题色，不铺满背景。

使用 [Emil Kowalski 的 emil-design-eng](https://github.com/emilkowalski/skills/tree/64eb3deb9a5fbfa041faf783e0bc3fd635872e9c/skills/emil-design-eng) 与作者的 apple-design 整理：用字重、基线、单位与间距精进原版。后者不是 Apple 官方 HIG，平台规则仍以本文件下方官方依据为准。

| Before | After | Why |
| --- | --- | --- |
| 首页plain点击无统一反馈 | 按下约100ms、释放约140ms的轻微缩放/透明度反馈 | 动作立即执行，不等待导航或网络 |
| 日期没有连续选择指示 | 日期稳定标识、约200ms轻选择转场，重复点同一天不重播 | 将选择与所选日数据联系起来 |
| 主值采用较重圆角数字 | 系统semibold、等宽数字与基线单位 | 保留原版辨识度，减少重量竞争 |
| 长分析首段2行、末段1行 | 长文摘要120pt，15pt语义正文最多4行，全文在详情 | 不无限缩字、不让长文冲破一屏 |
| 未来日无障碍文本可能读成零组 | 明确“未来日期”与计划简称 | 未发生数据不冒充零 |

动效仅为按下、日期选择与真实数值变化；不做开屏分段入场、从零重数、循环转环、背景漂浮或重blur。常规转场不超过约220ms，详情/标签采用系统NavigationStack、sheet、TabView。Reduce Motion取消按下缩放、日期空间位移与数字滚动，保留轻透明度反馈。

模拟器Debug的长文/减少动态效果夹具仅用于核对同一界面，Device Release不含这些入口。构建与实际验收另行记录，未取得截图或运行证据时不宣称通过。

1.3 本轮最终验收范围：设备 Release IPA、模拟器 Debug 与 UI 测试包编译通过，24 项核心检查和项目结构检查通过，IPA/实况扩展版本与完整性通过。用户随后明确要求“不用模拟器检查”，已停止该运行过程；不把空白启动帧或测试启动当作视觉、动效、深色/大字验收通过。没有进行真机帧率检查。

## 视觉规格（项目选择，不宣称是 Apple 强制数值）

- 系统分组背景，内容使用 secondarySystemGroupedBackground。蓝色取系统 blue，适应明暗外观；活动/力量/体态语义色沿用粉/绿/青。
- 页面水平边距 20 pt。总览卡片内边距 12 pt、间距 10 pt、圆角 20 pt，以适配一屏；详情卡片继续采用 16 pt 内边距、24 pt 圆角。
- 总览使用系统内联导航标题，训练和记录保留系统大标题。指标数字 34 pt 相对 largeTitle 缩放，单位与说明降低一级。
- 总览恢复/步数双列等高；辅助功能大字改为纵向，避免压缩和截断。
- 本轮安排只强调一个主开始操作，其余用次级按钮。训练分类使用字母与清楚的焦点名称，当前轮次以文字标记。
- 使用原生浮动标签栏，保持正常状态可见。训练是独立全屏任务，可收起并继续；结束保存后进入报告。
- 首页同步从日期旁入口进入；滚动详情支持下拉刷新。退出登录只放设置。

## 页面与流程

### 总览

顶部日期/同步状态与“记录感受” → 早/晚观察（周日 17:00 后换成本周小结）→ “目标”：所选日的三环图形（外圈活动、中圈力量两半、圆点体态）与步数小卡 → “本周”：七天图形、活动合计与力量指数，可就地展开 → 恢复 / 睡眠 / 体重三格。
层级规则：查看类详情（步数、体重与体型、每日记录、力量指数、数据与同步、训练日历、恢复与睡眠、观察）一律在总览的导航栈里推进；只有编辑类（目标、感受、散步时间）用 Sheet，且不在 Sheet 上再叠 Sheet。首页“日历”在总览内推进打开，不切换标签，也不改变运动记录页的列表/日历偏好。
周卡在本页选择日期，联动“所选日/本周”的日常活动、力量、体态三行；当日和选中状态分别表达。空数据为破折号，未来日期不当作零。详细活动拆分、训练记录和目标编辑按各自入口进入。睡眠与作息、心率变异性、静息心率和观察记录全部进入“恢复指数”详情，首页不再有这四行。标准字号在 iPhone 18 Pro 上采用一屏容器：观察 104 pt、双指标 112 pt、周卡使用剩余空间。更大字号保留完整内容并允许滚动，不缩小系统字体。

### 训练

当前安排（公司/家庭，完成数/目标数与开始/继续）→ 体态组 → A/B/E/C/D 分组。E 明确标为可选；当前轮次显示文字状态。展开分组后查看公司和家庭模板，再进入安排/编辑或直接开始。动作库、自由训练和全部模板放次级工具菜单，周肌群统计放页面后部。

### 运动记录

分类 → 系统搜索 → 可用月份 → 按日期分组的记录。每条只显示类型、名称、开始时间、实际时长、完成组及热身摘要；明细进入原生详情。本 App、训记和 Google Health 记录保持来源区分，删除仅适用于在线已保存的本 App 已完成记录。

### 恢复指数与睡眠详情

恢复指数详情先展示分数和依据，再提供睡眠、HRV、静息心率、观察记录四个入口。睡眠详情仍保留最近一晚的日期/睡眠窗口、实际睡眠、卧床时间 → 睡眠阶段图和图例 → 六项恢复指标。图表提前，减少长距离滚动；较早记录收为简洁的日期/时长列表，点击后查看完整详情。睡眠时长只用实际记录，不补造空晚；入睡用时 0 等有效值保留。

### 训练中与报告

保持一个动作的专注录入。44 pt 数字输入与完成按钮，聚焦全选，原生数字键盘；休息倒计时与暂停状态明确。报告保留实际组次、来源、比较条件和更正操作。设置/反馈/编辑复用原生 Form，取消不提交。

1.4 起的录入约定：
- 任意一组都能点开同一个组次面板：改重量/次数、记录吃力次数、切换热身、标记完成或未完成、删除。完成一组后 5 秒内底部显示“撤销第 N 组”。
- 改了当前组的数值、后面同类型的未完成组不同时，出现“后面 N 组也改成 …”。
- 休息时显示倒计时、刚完成的那组（可直接修改，一点记录“不吃力 / 最后 1 次 / 最后 2 次 / 3 次以上”）、下一组和整组列表。
- “动作 x / y”菜单显示每个动作的完成情况，可调整顺序；动作设置的要领、替换在同一个 Sheet 内推进。
- 每个器械动作可存一条长期的“器械设置备注”，显示在动作名下方。
- 一组都没完成时，收起或结束会提供直接放弃，不保存空记录。
- 只有计时、休息倒计时和最后三秒的按钮呼吸每秒刷新；整个录入页只在休息开始/结束和数据变化时重绘。
- 锁屏和灵动岛：训练中“完成本组”，休息中“+30 秒 / 跳过休息”，由 App 进程执行并更新实况。
- 结束后报告在开始训练的那个标签上弹出；当天还有家庭/公司另一半、体态未做或下一次安排时，报告里有“下一步”，另一半可设本地提醒。容量按本次多数组使用的单位显示。

### 1.2 性能修复

依据 [Apple Observation 迁移说明](https://developer.apple.com/documentation/swiftui/migrating-from-the-observable-object-protocol-to-the-observable-macro)，将全局 ObservableObject 改为按属性跟踪的 Observation，并按首页、目录、记录、历史等拆分可观察数据；不会因输入状态变化重新计算所有标签页。

- 训练编辑先原子写入小型增量事务，再确认界面更新；完整缓存整理在后台执行，保留旧缓存兼容、版本冲突和删除标记。无变化同步不写盘，空闲时不请求同步。
- 历史转换和周肌群统计按数据变化准备；记录时间线在后台构建，搜索直接筛选准备好的列表。日期解析和格式器复用有界缓存；肌群路径在后台准备一次，使用 Canvas 绘制。
- 输入重量/次数不会反复更新相同训练实况；完成组、休息、暂停等内容变化仍触发更新，前台恢复可强制刷新。
- Mac Release 微基准：1,000 条合成训练记录、7 次编辑，中位写入耗时 315.53 → 1.62 ms，单次数据 4,999,904 → 5,055 字节。1,000 次重复时间戳解析 499.82 → 0.25 ms。原始结果见 build/performance-1.2.json。**这些是算法/磁盘基准，不是 iPhone 帧率或用户真机流畅度结论。**
